# 2026-08-10 v0.9 迭代 — Textual 全屏 TUI

## 触发原因

v0.8 TerminalChannel（Rich + prompt_toolkit）问题：
1. 流式输出无历史 scrollback，长对话看不见上文
2. Markdown 不渲染，代码块挤在 plain text 里
3. reasoning / tool 输出混在主流里，视觉混乱

Claude Code 类全屏 TUI 是用户已经习惯的形态。

## 选型

**Textual**（Python 终端 TUI 框架）：
- 完整 `Markdown` widget（流式 token 增量 update）
- `VerticalScroll` 自动 scroll-to-bottom
- `@work` 装饰器跑 async worker（与 message pump 同 loop）
- `Input` widget 自带 `Submitted` 事件（Enter 提交）
- TCSS 样式（类 CSS 语法）
- 已确认实测可用：参考实现 [Elia](https://github.com/darrenburns/elia)

不用 urwid / py-cui：Textual API 现代、async native、Textualize 团队（Rich 作者）维护。

## 架构

core/ 保持零 UI 依赖。新增 `extensions/channels/textual_chat.py` 实现 `Channel` 协议：

```
Gateway.run()
  ├─ TextualChannel.start()
  │    └─ ChatApp.run_async()       ← 同 asyncio loop
  │         ├─ _drain_outbound (@work)
  │         │    └─ out_q.get() → _handle_event(ev)
  │         └─ ChatScreen (Header + VerticalScroll + Input + StatusBar + DebugPanel)
  ├─ _pump_inbound  ← channel.listen()  ← TextArea.Submitted → in_q
  └─ _pump_outbound → channel.send()    → out_q
```

**关键：同 asyncio loop**——`@work(exclusive=True, group="drain")` 跑 drain worker；`put_nowait` 在同 loop 直接写 queue；`call_after_refresh` 调度 widget 更新。无需 `call_from_thread`。

## Widget 列表

| Widget | 作用 |
|---|---|
| `Header (Static id=app-header)` | 顶部 1 行 `MonoX · {session_key}` |
| `VerticalScroll id=history` | 主区，自动滚到底 |
| `UserMessage(Static)` | 用户消息加粗 |
| `AssistantMessage(Markdown)` | 流式 markdown，节流 16fps（`call_after_refresh` flush） |
| `ReasoningMessage(Static)` | 灰色 italic，累积 flush |
| `ToolCard(Static, cyan border)` | tool name + args → 完成后填 stdout/stderr/exit/latency |
| `StatusBar(Static)` | 底部状态，`thinking` 时挂 `LoadingIndicator` |
| `DebugPanel(Static)` | 右侧 40%，F12 切显隐 |
| `Input id=prompt` | 单行 prompt，Enter 提交 |
| `Footer` | 显示 F12 / Ctrl+C |

## StreamEvent 映射

| Event | widget 操作 |
|---|---|
| `ReasoningChunk` | 累积到当前 `_cur_reasoning`；下一个非 reasoning event 时 freeze |
| `TokenChunk` | 累积到 `_cur_assistant` 缓冲；`_schedule_flush` 节流 `Markdown.update` |
| `ToolStart` | freeze assistant + 创建 `ToolCard` |
| `ToolEnd` | 完整 ToolCard（stdout/stderr/exit_code/latency） |
| `StatusChange` | 更新 StatusBar 文本 + loading class；debug 面板追加行 |
| `MetricChunk` | debug 面板追加一行（`step / latency / tools / in / out`） |
| `FinalMessage` | freeze 所有 in-flight；final summary |
| `Card` | 挂 `Static(json.dumps)` |
| `ErrorEvent` | 挂红色 `Static` |

## 关键技术坑

| 坑 | 解决 |
|---|---|
| `asyncio.create_task` 在 App 上下文外 → 跨 loop Queue 不通 | 用 `@work(exclusive=True, group="drain")` 让 worker 在 App loop 跑 |
| `Markdown.update()` 是 async (returns AwaitComplete)，fire-and-forget 后 mount blocks 不执行；初始 mount 时 `_on_mount` 调 `update("")` 异步覆盖 | `AssistantMessage.update` override：空 markdown 时返回 no-op awaitable（保留 awaitable 接口） |
| `call_after_refresh` 是单次 refresh；持续 token 流要 throttle | 自己实现 `_schedule_flush`：dirty flag + `_scheduled` flag |
| Markdown widget 内部 reparse cost 高（>2KB 流卡顿） | 节流到 ~16fps（每次 `_schedule_flush`） |

## 用法

```bash
uv lock && uv sync                    # 拉 textual

# config.toml 改 channel kind
sed -i 's/kind = "terminal"/kind = "textual"/' config.toml

uv run python run.py                  # normal TUI
uv run python run.py --debug          # debug 面板初始可见
```

F12 切 debug / Ctrl+C 退 / 输入 `exit` 退。

## 已知保留问题

**Engine 不响应 channel 关闭**：用户 `exit` 退出 TUI 后，engine 仍在 `input_queue.get()` 阻塞。整个 process 还在跑。要等下次用 `shutdown_event` 一起处理（影响 core loop engine）—— 现在跟 TerminalChannel 一致。
