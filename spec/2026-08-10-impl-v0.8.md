# 2026-08-10 v0.8 迭代

## 触发原因

用户想看到 ReAct loop 的运行细节（state / step / latency / tokens）。
类似 Claude Code：默认干净，但有开关能看到内部。

## 分档原则

**思考内容不是 debug，是基本 output。** debug 只加"更细节的运行时信息"。

| 档 | 显示 |
|---|---|
| normal（默认） | `TokenChunk` `ReasoningChunk` `ToolStart` `ToolEnd` `FinalMessage` |
| debug（`--debug`） | 上述 + `StatusChange` + `MetricChunk` |

- `ReasoningChunk`：模型在想什么，正常用户也想看 → normal 就显示
- `StatusChange` / `MetricChunk`：loop 内部机制 → 只有 debug 才显示

## 开关

只走命令行参数，不用环境变量（避免隐式状态）：

```bash
uv run python run.py            # normal
uv run python run.py --debug    # debug
```

## 改动

| 文件 | 改动 |
|---|---|
| `extensions/channels/terminal.py` | `debug` 参数 + reasoning buffer 累积 flush + 各事件分档 |
| `run.py` | `argparse --debug` + 透传给 `build_channel` |

### reasoning buffer

`ReasoningChunk` 流式到达但碎片化，逐 chunk 打印会刷屏。
策略：累积到 buffer，遇到第一个非 reasoning event 时整体 flush。

```python
if isinstance(event, ReasoningChunk):
    self._reasoning_buf += event.text
    return
if self._reasoning_buf:
    self.console.print(f"[grey50 italic]💭 {self._reasoning_buf.rstrip()}[/grey50 italic]")
    self._reasoning_buf = ""
```

# v0.8.2 —— spinner + 运行时 debug toggle

## 触发原因

v0.8 用户实测：
1. token 到达前 LLM 思考耗时没视觉反馈（等几秒不知道在干啥）
2. `--debug` 是单次决定，不能中途切换

## 改动

### spinner

`StatusChange(state="thinking")` 触发 Rich `Live(Spinner("dots", text=" thinking"))`，
下一个非 reasoning event（token / tool / metric）来到时 `_stop_spinner()`。
非 thinking state（如 `tooling`）仍打印行 —— 状态切换明确，spinner 只是 thinking 占位。

```python
self._spinner = Live(
    Spinner("dots", text=f" {state}", style="bold magenta"),
    console=self.console, transient=True, refresh_per_second=12,
)
self._spinner.start()
```

`transient=True` 让 stop 时自动擦除行，不留残影。

### F12 toggle

`prompt_toolkit.KeyBindings` 挂在 `PromptSession` 上：

```python
@kb.add("f12")
def _toggle_debug(event):
    self._debug = not self._debug
    self.console.print(f"[dim]debug view: {on/off}[/dim]")
```

构造参数 `debug` 仍决定初始值，`--debug` 启动则初始 on，运行中可关。
