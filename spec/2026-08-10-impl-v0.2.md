## 关键设计变化

### wait_io 从状态 → tool

**v0.1**: `awaiting_human` 状态 → wait_io 状态（泛化外部等待）

**v0.2**: `wait_io` 改为内置 tool。理由：
- 状态机里多一个特殊状态 = 多一份复杂度
- 用 tool 表达"agent 想停下来" = 复用现有 tool 调用机制
- agent 主动调 wait_io = agent 自己决定何时停

**loop 结束判定**（agent 视角）：

```
agent 完成 final message:
  - input_queue 有新事件 → aggregate，继续 react
  - input_queue 没事件 → 进入 wait_io 状态，react 结束

agent 调 wait_io tool:
  - 立即跳出 react，进入 wait_io 状态

达到 max_steps:
  - 返回 "[max_steps reached]"
```

### Interrupt 改为 Queue Aggregate

**v0.1 设计**：InboundEvent.kind="interrupt" 触发 cancel 当前 react

**v0.2 设计**：取消 interrupt 特殊事件，用户消息直接进 queue。Loop 每 step 开始 `_drain(input_queue)`，聚合所有新 user 消息到 messages。

```python
for _ in range(max_steps):
    for ev in _drain(input_queue):
        self._messages.append({"role": "user", "content": ev.text})
    # ... LLM call ...
```

**好处**：完全复用现有事件流，零特殊机制。

### LLMProxy Protocol 完整性

只暴露 `stream(messages, tools, options)` → `AsyncIterator[LlmChunk]`。

```python
class LLMProxy(Protocol):
    async def stream(
        self,
        messages: list[dict[str, Any]],
        tools: list[dict[str, Any]] | None = None,
        options: dict[str, Any] | None = None,
    ) -> AsyncIterator[LlmChunk]: ...
```

**options 字段**（预留 harness）：
- `temperature` / `top_p` / `max_tokens` / `response_format` / `stop`
- v0 harness 暂不实现，只透传到 OpenAI API

**LlmChunk 字段**：
- `delta_text` / `delta_tool_calls` / `finish_reason` / `usage`

**v0 harness 不实现**：retry / fallback / 限流 / token 预算。LLMProxy 内部唯一职责：闭环 stream。

## 测试覆盖

`tests/test_e2e.py` 3 个场景：

1. **test_basic_bash**: bash tool 真实执行（echo hello），2 次 LLM 调用
2. **test_wait_io_ends_turn**: agent 调 wait_io → react 立即结束（只 1 次 LLM 调用）
3. **test_queue_aggregate_continues_react**: final message 时 input_queue 有新事件 → aggregate 继续 react（2 次 LLM 调用，最终 reply 是第二次的）

## 踩过的坑

1. **engine.py import ToolRegistry from core.protocol**：ToolRegistry 在 core.loop.tool_registry，不在 protocol。重写时漏改。
2. **Test race condition**：main 用 `await asyncio.sleep(0.2)` 后 put second 到 input_q，但 _react 跑得很快，drain 在 put 之前就完成。改用 MockLLM 加 `step_delay=0.3` 模拟真实 LLM 延迟，让 _react 慢下来，main 才有时间 put。
3. **wait_io execute 调用**：v0.1 没这个 tool，engine 里 if name == "wait_io" 时直接 mock 一个 ok result。改成 if name == "wait_io" 时调 WaitIoTool.execute（也返回 ok），保持 tool 真有 execute 调用。
